# tbot

Telegram-интерфейс управления. Команды меняют список слежения в общей базе `~/.cbr/data/cbr.db`,
а владельцу приходит сообщение, когда recorder выключил пользователя (status API ответил 4xx) или удалил
его из списка (существовавший пользователь трижды подряд, раз в сутки, ответил 404/410).
О каждой записи бот не пишет: что пишется сейчас, видно в `/list`, а полный журнал — в `GET /events` у api.
С recorder напрямую не общается: если tbot выключен, запись продолжается, а пропущенные события бот
дошлёт после запуска (позиция в журнале хранится в базе, при самом первом запуске история пропускается).

| Команда | Что делает |
|---|---|
| `/add <user>` | добавить пользователя (или снова включить выключенного). Бот отвечает после первой проверки recorder'ом (обычно 5–8 с, не дольше 30 с): «added (offline)», «access denied, checking daily», «not found, not added» (пользователя нет — в список он не попадает) или «recorder has not checked it yet», если recorder не успел. Вместо имени можно прислать ссылку на страницу (`https://site/<user>`, `https://site/<раздел>/<user>/`) — сохраняется только имя |
| `/del <user>` | убрать пользователя (имя или ссылка); без аргумента — меню с кнопками |
| `/list` | список с состоянием: 🔴 запись, 👀 слежение и статус комнаты, 🚫 доступ запрещён (401/403), ❓ не найден (404/410) — оба проверяются раз в сутки, ⏸ выключен (с причиной), ⏳ recorder ещё не подхватил |

Команды принимаются только от `allowed_user_id`, остальным отвечает «Access denied.».

## Конфиг `~/.cbr/config/tbot.json`

```json
{
  "bot_token": "<токен от @BotFather>",
  "allowed_user_id": 123456789,
  "proxy": ""
}
```

`proxy` (необязательно) — HTTP-прокси для Telegram API. Шаблон — [config.example.json](config.example.json).

## Запуск

```bash
make run                         # локально
services/deploy/install.sh tbot  # на сервере: unit cbr-tbot.service
```

Флаги: `-debug`, `-version`.
