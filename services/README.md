# services

Бэкенд cbrmedia для Ubuntu: четыре независимые systemd-службы над общей служебной папкой `~/.cbr`.
Каждую можно включать и выключать отдельно — остальные продолжают работать.

| Служба | Что делает | Пишет | Читает |
|---|---|---|---|
| [recorder](recorder/README.md) | опрашивает status API и записывает стримы | `recordings/`, состояние и события в базе | список слежения |
| [tbot](tbot/README.md) | Telegram: `/add`, `/del`, `/list`, уведомления о выключенных и удалённых пользователях | список слежения | состояние, события |
| [api](api/README.md) | HTTP API плеера: видео, список слежения, события | список слежения, удаляет видео | `media/`, база |
| [converter](converter/README.md) | `recordings/` → HLS в `media/` (ffmpeg) + `meta.json` | `media/` | `recordings/` |

Каждая служба раз в несколько секунд отмечается в базе (heartbeat: имя, версия, время); `GET /health` у api показывает,
кто запущен и какой версии. Без живого recorder api и tbot на добавление пользователя отвечают сразу, не ожидая проверки.

`core/` — общая библиотека: служебная папка, база, конфиги, запуск, метаданные видео (`meta.json`).

## Как службы связаны

Напрямую — никак. Общение идёт через общую базу `~/.cbr/data/cbr.db` (SQLite, WAL) и через файлы:

```
 tbot / api / (WhatsApp…) ──пишут──▶ watchlist ──читает раз в 3 с──▶ recorder ──▶ recordings/ ──▶ converter ──▶ media/ ──▶ api
                ▲                                                       │
                └──────────── events, watch_state ◀──────── пишет ──────┘
```

- **watchlist** — кого записывать. Интерфейсы не отдают команд recorder: они меняют список, а recorder сам
  сверяется с ним. Новый интерфейс (например, WhatsApp) — это новая служба, которая пишет в ту же таблицу.
- **watch_state** — что recorder делает сейчас (статус комнаты, идёт ли запись).
- **events** — журнал событий. Каждый читатель хранит свою позицию в `cursors`, поэтому выключенный бот
  после запуска дошлёт пропущенное.
- **services** — heartbeat служб: кто запущен, какой версии, когда отмечался. Корректно остановленная служба
  удаляет свою строку.

База — SQLite в режиме WAL, её одновременно открывают все службы. Это работает только на локальном диске одной
машины: служебная папка на сетевом диске (NFS, SMB) ломает блокировки WAL и может повредить базу. Службы одной версии
обновляются вместе (`install.sh` без аргументов): бинарник старее схемы базы не стартует.

## Служебная папка `~/.cbr`

Переопределяется переменной `CBR_HOME`. Службы сами создают недостающие папки и работают из `~/.cbr`,
поэтому неважно, откуда запущен бинарник. Пути описаны в одном месте: `core/home`.

```
~/.cbr/
├── bin/                 # recorder, tbot, api, converter
├── config/
│   ├── recorder.json    # base_url, proxy
│   ├── tbot.json        # bot_token, allowed_user_id, proxy (chmod 600)
│   ├── api.json         # addr (по умолчанию :8000), status_base_url, proxy — всё необязательно
│   └── auth.json        # хэш пароля плеера (api hash-password)
├── data/
│   ├── cbr.db           # общая база (SQLite)
│   └── converter.lock
├── recordings/          # сырые записи (*.ts / *.mp4, part-файлы); failed/ — не удалось преобразовать
├── media/               # HLS-библиотека плеера (<папка>/playlist.m3u8 + meta.json)
└── logs/                # <служба>.log, ротация через logrotate
```

## Разработка

Требуется **Go 1.26+** (патч-версия закреплена в `go.mod`, Go скачает её сам). Каждая служба — отдельный
Go-модуль; `core` подключается через `replace cbr/core => ../core`.

```bash
./dev.sh                    # собрать и запустить весь back-end локально (macOS/Linux)
./dev.sh recorder api       # только эти службы
make test                   # тесты всех модулей
make check                  # vet + golangci-lint + test + govulncheck по всем модулям
```

`dev.sh` работает со служебной папкой `~/cbr-dev`, чтобы не трогать `~/.cbr` (другую задаёт `CBR_HOME`).
Перед первым запуском:

1. `./dev.sh` — соберёт бинарники в `~/cbr-dev/bin/` и положит шаблоны `recorder.json` и `tbot.json` в `~/cbr-dev/config/`;
2. заполнить конфиги и задать пароль плеера: `CBR_HOME=~/cbr-dev ~/cbr-dev/bin/api hash-password --password <пароль>`;
3. `./dev.sh` ещё раз — службы запустятся в этом терминале, вывод каждой с префиксом `[служба]`,
   копия в `~/cbr-dev/logs/`. Ctrl+C останавливает все.

Если на сервере уже работает бот с тем же токеном, локальный tbot будет получать `409 Conflict`: заведите
тестового бота или запускайте без него (`./dev.sh recorder api converter`). converter нужен ffmpeg
(`brew install ffmpeg`); локально он проверяет записи каждую минуту (`CONVERT_INTERVAL`). Подробные логи — `DEBUG=1 ./dev.sh`.
Одну службу без сборки можно запустить через `go run`: `CBR_HOME=~/cbr-dev make -C api run`.

В папке модуля доступны те же цели (`make help`). Общий конфиг линтера — `.golangci.yml`, общие цели — `common.mk`.

## Деплой на Ubuntu

```bash
services/deploy/install.sh                 # все службы
services/deploy/install.sh recorder tbot   # только эти
sudo systemctl disable --now cbr-tbot      # выключить службу
tail -f ~/.cbr/logs/recorder.log
```

Скрипт делает `git pull`, собирает бинарники в `~/.cbr/bin/`, перезаписывает unit-файлы `cbr-<служба>.service`
и запускает службы. Если для службы нет конфига, кладёт шаблон и пропускает её. Ротация логов
(`/etc/logrotate.d/cbrmedia`): раз в сутки (`maxsize 100M` проверяется только при этом запуске — файл больше
100 МБ ротируется на ближайшем, а не сразу), 14 архивов, `copytruncate`.
Прежние монолитные службы `cbrservice` и `cbrconvert` скрипт останавливает и удаляет.
