# recorder

Служба записи стримов. Берёт список слежения из общей базы `~/.cbr/data/cbr.db`, опрашивает status API
по каждому включённому пользователю и, когда стрим начинается, записывает его как HLS без ffmpeg
в `~/.cbr/recordings/`. Состояние (статус комнаты, идёт ли запись) и события пишет обратно в базу —
их показывают интерфейсы управления ([tbot](../tbot/README.md), [api](../api/README.md)).

## Как работает

- **Сверка со списком.** Каждые 3 секунды recorder читает включённых пользователей из `watchlist` и
  запускает или останавливает слежения. Команд он не получает: чтобы начать запись, достаточно добавить
  пользователя в базу (через tbot, api или любой другой интерфейс).
- **Опрос.** Интервал зависит от статуса комнаты: 15 секунд, если стрим публичный; 1 минута, если
  пользователь онлайн, но стрим недоступен (private, away, hidden, password protected); 15 минут, если офлайн.
  На 5xx и сетевые ошибки — пауза 20 минут и повтор; на 429 — по заголовку `Retry-After` (не дольше 20 минут),
  без него 2 минуты. Каждый запрос к status API ограничен 30 секундами, к CDN — 15 секундами на плейлист
  и минутой на сегмент, чтобы зависшее соединение не останавливало слежение.
- **Ошибки 4xx от status API:**
  - 404, 410 — пользователь не найден. Если status API ещё ни разу не ответил о нём успешно (только что
    добавлен с опечаткой или несуществующим именем), он сразу удаляется из списка — событие `user_rejected`
    (добавивший узнаёт об этом из ответа api или tbot, поэтому в Telegram оно не пересылается). Подтверждённый (флаг `verified` в базе ставится при первом успешном ответе) остаётся
    со статусом `not found` в `watch_state` и проверяется раз в сутки; после 3 таких ответов подряд удаляется,
    событие `user_removed`. Счётчик живёт в памяти: успешный ответ или перезапуск recorder начинают отсчёт заново;
  - 401, 403, 451 — доступ запрещён, обычно временная блокировка: пользователь остаётся в списке,
    в `watch_state` статус `blocked`, следующая проверка через сутки;
  - прочие 4xx — пользователь выключается (`enabled = 0`, с причиной), событие `user_disabled`;
    повторное добавление включает его снова.
- **Запись HLS.** Выбирает вариант с максимальным битрейтом из master-плейлиста, непрерывно скачивает
  новые сегменты, расшифровывает AES-128, поддерживает fMP4/CMAF с init-сегментами (part никогда не
  содержит фрагменты без init; новый init начинает новый part). Запись заканчивается на `#EXT-X-ENDLIST`,
  при ответе 4xx на плейлист или если 1 минуту (или 6× target duration, что больше) не удалось записать
  новый сегмент — это ловит CDN, которые продолжают отдавать застывший плейлист после конца эфира.
  Сегменты пишутся строго в порядке плейлиста: не скачавшийся сегмент повторяется при следующей перезагрузке
  (следующие ждут), после 3 неудач подряд пропускается.
- **После записи.** Если запись шла дольше минуты, status API опрашивается сразу (запись могла оборваться
  посреди стрима, например из-за истёкшего CDN-токена, — продолжение пойдёт в новый файл); после короткой —
  обычная пауза. Если записать не удалось (ошибка или ни одного сегмента — `recording_failed`), следующая
  попытка через 15 с, затем паузы удваиваются до 15 минут; счётчик сбрасывается удачной записью или концом стрима.
- **Файлы.** `<user>_<дата>_part<N>.ts` или `.mp4` в зависимости от формата; part ротируется после каждого
  часа записанного контента. Пока part пишется, у него суффикс `.download`; незавершённые после падения
  part'ы восстанавливаются при старте. Существующие файлы не перезаписываются.
- **События** в журнал: `recording_started`, `recording_finished`, `recording_failed`, `user_disabled`, `user_removed`, `user_rejected`.
  События старше 30 дней удаляются.
- **Проверка TLS-сертификатов отключена** для опроса и скачивания (при старте пишется предупреждение).

## Диагностика: `hlsprobe`

Утилита для разбора реального поведения status API и CDN (ничего не пишет в базу и в recordings):

```bash
go build -o bin/hlsprobe ./cmd/hlsprobe                                   # или GOOS=linux GOARCH=amd64 для сервера
bin/hlsprobe [-wait 30m] [-reloads 6] [-segments 3] [-out DIR] <user или ссылка>
```

С настройками dev проще через `services/dev_probe.sh <user или ссылка>` (пользователь в эфире): собирает утилиту,
задаёт параметры (несуществующий `neverexistinguserbla`, ожидание эфира до 5 мин, 5 минут перезагрузок плейлиста,
4 сегмента) и кладёт результат в корень репозитория.

`base_url` и `proxy` берёт из `recorder.json` (флаги `-base-url`, `-proxy` переопределяют). Запрашивает статус
пользователя (как есть, в исходном регистре, в верхнем и заведомо несуществующего — чтобы увидеть коды ответов),
master- и все media-плейлисты, `-reloads` раз (или в течение `-duration`) перезагружает лучший вариант (видно, меняются ли токены в URL
сегментов и как растёт `MEDIA-SEQUENCE`), скачивает ключи, init и последние `-segments` сегментов, затем свежий
`hls_source`; для звуковых дорожек (`#EXT-X-MEDIA`) — плейлист, init и сегменты с номерами для сравнения с видео.
Тексты master- и media-плейлистов попадают в `summary.txt` целиком. Результат — папка `hlsprobe-<время>/`: тела
ответов, `requests.jsonl` (URL, код, заголовки, время) и `summary.txt`. Ссылки во всём сохранённом и напечатанном
замаскированы (`cmd/hlsprobe/mask.go`): хосты в ссылках и любые доменные имена в тексте (заголовки CSP, JSON,
HTML-страницы ошибок; хост каждого запроса и его домен второго уровня вычищаются в любом окружении) → `host1`…, значения query → `v1`… (одинаковые значения — одинаковые
метки, смена токена или edge-сервера видна), имя пользователя → `<user>`/`<USER>`/`<User>` по регистру, cookies
скрыты; пути и имена сегментов остаются. Папка в `.gitignore` — в ней сегменты и ключи.

## Конфиг `~/.cbr/config/recorder.json`

```json
{
  "base_url": "https://example.com/api/streamcontext",
  "proxy": "http://127.0.0.1:8080"
}
```

- `base_url` — базовый адрес status API; пользователь опрашивается по `<base_url>/<user>/`, ответ содержит
  `room_status` и, если стрим идёт, `hls_source`.
- `proxy` (необязательно) — HTTP-прокси для опроса и скачивания.

Шаблон — [config.example.json](config.example.json). Ошибки в конфиге останавливают службу при старте.

## Запуск

```bash
make run                       # локально, данные в $CBR_HOME (по умолчанию ~/.cbr)
services/deploy/install.sh recorder   # на сервере: unit cbr-recorder.service
```

Флаги: `-debug`, `-version`.
