## Решено не исправлять

Решение владельца от 2026-11-10, по итогам проверки v1.3.0 (`7bb125c`). Номера в скобках — пункты того отчёта.

### I-1. Дата видео сбивается при дозаписи `meta.json` (п. 1)

`createdAt` в `GET /videos` — mtime папки видео (`services/api/internal/library/media_data.go`, `CreatedAt`).
`backfillMeta` в converter создаёт в папке файл и меняет mtime, поэтому у видео, опубликованных до 1.3.0,
в списке стоит дата обновления сервера. У новых видео дата — момент публикации. Настоящая дата записи есть в имени папки.

### I-2. Отказы записи никому не сообщаются (п. 6)

В Telegram уходят только `user_disabled` и `user_removed` (`forwardKinds` в `services/tbot/internal/telegram/bot.go`).
`recording_failed`, ошибки converter и остановленный recorder видны только в логах, `GET /events` и `GET /health`,
которые клиенты не читают. Если status API перестанет отдавать `hls_source`, recorder не пишет и ошибок не даёт.

### I-3. Заполнение диска не контролируется (п. 7)

- Converter при любой ошибке ffmpeg, включая нехватку места, уносит запись в `recordings/failed/` и больше её не трогает;
  папка не чистится.
- Recorder при полном диске на каждой попытке оставляет пустой part-файл.
- Автоудаления старых видео из `media/` нет.

### I-4. Нет ограничения попыток входа (п. 8)

`POST /auth` не ограничивает частоту: 20 неверных паролей проходят за 1,15 с (замер 2026-11-10).

### I-5. tbot может перестать пересылать события (п. 10)

- Ошибка чтения курсора при старте завершает `ForwardEvents` до перезапуска службы.
- Событие, которое Telegram не принимает, повторяется каждые 3 с и не пропускает следующие.

### I-6. Токен в Keychain не используется при запуске (п. 12)

Приложение всегда открывает экран входа (`apps/ios/CBRPlayer/Scenes/FSPlayerView.swift`), сохранённый токен
вход не пропускает. Действует один токен: вход с одного устройства отзывает токен остальных.
