## 2. Текст ошибки входа

- `POST /auth` отдаёт ошибки простым текстом через `fiber.NewError`: `invalid password`, `invalid json`,
  `failed to issue token` (`services/api/internal/httpapi/auth.go`, `authHandler`).
- iOS ждёт JSON `{"error": "..."}` (`apps/ios/CBRPlayer/Services/AuthService.swift`, `AuthErrorResponse`),
  не разбирает ответ и показывает «HTTP Error: 401».
- Остальные маршруты отвечают JSON через `jsonError`.
- Проверено: `curl` на `/auth` с неверным паролем — `Content-Type: text/plain`, тело `invalid password`;
  в симуляторе на экране входа — «HTTP Error: 401».
- Исправление затрагивает контракт: формат ошибок `/auth` дописать в `CLAUDE.md` и `services/api/README.md`.

## 3. Общий сбой status API

Ошибки status API разбираются по каждому пользователю отдельно (`services/recorder/internal/recorder/watch.go`,
`classifyFailure` в `delay.go`). Если причина общая для всех, последствия такие:

- 401/403/451 (блокировка IP сервера, анти-бот, лимит) — все опрошенные получают `blocked` и следующую проверку
  через сутки (`dailyDelay`). Событий нет, в Telegram ничего не уходит.
- 404/410 три дня подряд (сменился путь API, ошибка в `base_url`) — подтверждённые пользователи удаляются,
  список слежения пустеет. `user_removed` приходит только на третий день; новые пользователи отклоняются сразу.
- Прочие 4xx — все выключаются, каждого включать заново вручную.

Что status API отвечает на заблокированного пользователя, не проверено (`services/CLAUDE.md`, «Не проверено»).

## 4. Пауза 20 минут после сетевой ошибки

- Запись завершается после 5 ошибок плейлиста подряд с паузой 3 с (`errStreak` в
  `services/recorder/internal/hls/recorder.go`) или через минуту без нового сегмента.
- После долгой записи статус опрашивается сразу. Если сеть ещё не вернулась, `Fetch` возвращает статус 0,
  и слежение уходит в `techFailure` = 20 минут (`delay.go`, `watch.go`).
- То же при разовом 5xx от status API.
- Итог: обрыв сети на 20–30 секунд посреди эфира даёт дыру в 20 минут.

## 5. Окно плейлиста

- После прохода с новыми сегментами recorder спит полный target duration (`reloadDelay` в
  `services/recorder/internal/hls/recorder.go`), время скачивания из паузы не вычитается, сегменты качаются по одному.
- Замер 2026-11-06 (`services/CLAUDE.md`): target 2 с, сегмент 1,6 с, в плейлисте 4 сегмента, сегмент 1080p
  качается 0,7–1 с.
- Расчёт цикла `T = 2,2 + (T / 1,6) × d`, где `d` — время скачивания сегмента: при `d` = 0,85 с цикл 4,7 с и
  2,9 сегмента за цикл; при 1,0 с — 3,7; при 1,1 с — 4,4, это больше окна.
- Сегменты сравниваются по пути URL (`SegmentKey`), номера `MEDIA-SEQUENCE` не сверяются, поэтому выпавший из окна
  сегмент не попадает ни в лог, ни в события.
- На живом стриме потери не замерялись.

## 9. Ротация логов

- Unit пишет лог через `StandardOutput=append:$CBR_HOME/logs/<служба>.log` (`services/deploy/install.sh`).
  systemd открывает файл до смены пользователя, новый файл принадлежит root.
- `services/deploy/logrotate.conf` работает с `su <user> <group>` и `copytruncate`: обнулить файл root он не сможет.
- `install.sh` файлы логов заранее не создаёт и владельца не меняет; `logrotate -d` в нём такую ошибку не ловит.
- Не проверено. На сервере:

```bash
ls -l ~/.cbr/logs
```

```bash
sudo logrotate -v /etc/logrotate.d/cbrmedia
```

## 11. Дубликаты видео

- Если `os.Remove(src)` не удался, converter пишет ошибку в лог и всё равно публикует видео
  (`services/converter/internal/converter/converter.go`, `convert`).
- Исходник остаётся в `recordings/`, и каждый проход (5 минут) публикует ещё одну копию: `_2`, `_3`…
- Нужен неудаляемый файл в `recordings/`: чужой владелец, read-only раздел.

## Документация

- **D1.** Устаревшие комментарии «api посчитает сам»: пакет `services/core/media/media.go` и `convert` в
  `services/converter/internal/converter/converter.go`. С `7bb125c` api метаданные не считает.
- **D2.** `apps/ios/README.md` описывает только список видео, без Watchlist и живого просмотра.
- **D3.** В дереве корневого `README.md` нет `design/`.
- **D4.** В `services/README.md` у `api.json` указан только `addr`, без `status_base_url` и `proxy`.
- **D5.** `services/README.md`: «раз в день или больше 100 МБ». logrotate запускается раз в сутки, `maxsize` чаще
  не сработает.
- **D6.** `MARKETING_VERSION = 1.0` в `apps/ios/CBRPlayer.xcodeproj` при версии проекта 1.3.0.
- **D7.** Не описано, что поле «IP or hostname» работает с IP и коротким именем. Вход по IP проверен; полное
  доменное имя по plain HTTP iOS должен блокировать (ATS, ключей исключений в проекте нет) — не проверено.
- **D8.** Нет раздела об эксплуатации: объём диска, резервная копия `cbr.db` и `auth.json`, что делать с
  `recordings/failed/`.
